# Capture detail

The capture-detail setting changes Agent observation work. It is independent of
the API-selection profiles and the optional native stack frame limit. The
compatible default is `preview`.

| Detail | Observed data | Work omitted |
|---|---|---|
| `metadata` | API identity, process/thread, raw return and error state, timing, call identity, hook context, optional stack | Argument payload callbacks and observation-only argument reads |
| `arguments` | Metadata plus existing scalar, pointer, string and structure decoders and synchronous I/O output counts | File, registry-value and generated byte-buffer previews |
| `preview` | Existing argument decoding and bounded byte-buffer previews | None of the existing payload collection |

`arguments` includes pointed strings and structures. It is not a no-memory-read
mode. The enabled decoders still determine what an individual API records. A
mode label does not establish complete argument coverage or successful reads.
Loader and resolver work needed to maintain hooks still executes in every mode.
Optional stack unwinding also reads thread memory; its bounds and provenance
remain governed by [the stack contract](stack-observation.md).

The native helper accepts `--capture-detail metadata|arguments|preview` for
launch, bounded or streaming attach, process-tree supervision and daemon
sessions. The desktop control is locked while a capture or its terminal drain
is active. Each new API event carries `captureDetail` through live transport,
the Rust host, UI conversion, saved sessions and export. Legacy events without
the field remain unspecified.

Transport ABI 10 and attach-config ABI 6 carry the detail explicitly. The
Controller validates the request before target setup and binds each record's
detail to the trusted session configuration. Metadata records containing
argument slots or payload text are rejected; generic API identity text remains
allowed. JSON consumers reject unknown or null detail, metadata events with
arguments, and disabled top-level buffer previews containing data. These checks
validate the record contract; they do not authenticate a compromised target.

The Agent skips argument callbacks before any decoder work in metadata mode.
It also gates observation-only pre/post reads outside those callbacks, including
file I/O, adapter-size and RPC-lifetime observations. Typed arguments remain
entry observations when enabled. In arguments mode, disabled I/O previews have
`decodeStatus: not_captured`, phase `none`, zero captured bytes and reason
`capture_detail`; synchronous transferred counts are still separate observations.

Read buffers are observed only after synchronous success and a valid transferred
count. Pending asynchronous output remains untracked. The underlying rules were
checked on 2026-09-21 against Microsoft's
[ReadFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile),
[WriteFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-writefile)
and [ReadProcessMemory](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-readprocessmemory)
contracts. Turning off observation avoids the corresponding read attempt;
removing data after collection would not provide that property.

Some legacy RPC decoders also copied a decoded string into the top-level
`bufferPreview` display field. In arguments mode that duplicate display is
omitted while the decoded string remains in its argument. This is separate from
skipping the actual file and registry buffer reads.

An argument marked `not_captured` stays visible and queryable, but it does not
count as a decoder failure. Highlights, issue groups, thread totals and timeline
buckets use that distinction. Actual partial, unreadable, invalid-pointer,
definition-missing and truncated results still produce decode warnings. API
return errors remain independent.

The test Agent counts actual observation-memory calls around controlled
originals. File I/O requires zero reads in metadata mode, one count read in
arguments mode and a count plus buffer read in preview mode. Inaccessible
pointers, noncanonical BOOL returns, error state, typed floating returns,
generic records, registry buffers and independently enabled stacks exercise
the production collection paths. Shared JSON fixtures exercise the native,
Rust, Node, UI and published schema contracts. Real desktop scenarios check
selection, capture-time locking, parameter presentation and export identity.

These controls enable separate cost measurements. They do not establish lower
overhead, competitive superiority or the full capture-profile-cost gate. That
gate also needs comparable latency, resource, delivery and UI measurements for
the same workload and explicit treatment of dropped events.
The [independent native profile matrix](native-profile-costs.md) measures the
caller portion and checks policy-specific payloads against its raw oracle.

Live launch and attach now publish `running` only after the Agent confirms the
requested capture detail and stack limit following initial hook installation.
See [capture readiness](capture-readiness.md) for ordering, deadlines and the
coordinated independent caller.
